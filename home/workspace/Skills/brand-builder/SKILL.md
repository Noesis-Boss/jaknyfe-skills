# Brand Builder

Build the smallest credible brand that can go live today. Favor clarity, evidence, consistency, and learning over polish. Do not invent credentials, results, testimonials, customers, or visual assets.

## Modes

Use **full mode** unless the user names a stage or asks for a specific deliverable. In full mode, run stages 1–8 in order and finish with a compact launch brief. In stage mode, run only the requested stage while using any existing brand context supplied by the user.

Ask only for missing information that materially changes the result. If information is unknown, label the assumption and continue with a usable draft.

## Eight-stage workflow

### 1. Essential-only brand scoping

Define:

- business or product
- target audience
- urgent problem solved
- offer or next action
- minimum brand elements needed to launch today
- work explicitly deferred as polish

Cut anything that does not improve understanding, trust, or action.

### 2. One core message

Write one sentence that explains what the business does, who it serves, and why it matters. It must be understandable by a stranger in five seconds without extra brand context. Provide up to three alternatives only when the positioning is genuinely ambiguous, then recommend one.

### 3. Minimum visual kit

Define the smallest usable kit:

- one primary color with hex code and purpose
- one accent color with hex code and purpose
- one practical Google Fonts pairing
- one simple text-based, monogram, or symbolic logo direction
- two or three visual rules that keep the brand consistent

Keep the logo concept feasible for a person to create in fifteen minutes. Do not produce an elaborate identity system unless asked. For premium visual boards or image generation, hand off to `brandkit`.

### 4. Single-page site structure

Create a minimal page outline containing:

1. headline using the core message
2. short context paragraph
3. proof or credibility section
4. one clear call to action

Do not add navigation, feature sprawl, or secondary sections unless the offer requires them.

### 5. Proof-first content

Identify the fastest truthful proof available now: early result, process detail, relevant personal experience, work sample, transparent newness, or specific guarantee. Write one short proof paragraph using only evidence supplied or clearly marked assumptions. If no proof exists, recommend an honest process-based proof asset.

### 6. Launch-ready copy

Write the complete single-page copy:

- headline
- context paragraph
- proof section
- CTA label and supporting line

Use simple, direct language. Remove placeholders unless the user explicitly wants a template. Never imply proof that does not exist.

### 7. Go-live checklist

Return a short checklist covering only launch blockers:

- core message is clear
- visual kit is applied consistently
- page loads and the CTA works
- contact or purchase method works

Flag no more than three issues that would embarrass the user or prevent action. Ignore cosmetic imperfections.

### 8. Post-launch iteration plan

Create a two-week learning plan. Specify the real signals to observe, such as visitor questions, CTA clicks, drop-off points, objections, and repeated confusion. Map each signal to one possible improvement. Do not recommend redesign based on taste alone.

## Output format

In full mode, use this structure:

# Lean Brand Launch Brief
## 1. Scope
## 2. Core message
## 3. Minimum visual kit
## 4. One-page structure
## 5. Proof
## 6. Launch copy
## 7. Go-live checklist
## 8. Two-week iteration plan
## Deferred work
## Assumptions and missing evidence

In stage mode, use the relevant section heading and include `Inputs used`, `Recommendation`, `Deliverable`, and `Next smallest action`.

## Quality rules

- Prefer one strong recommendation over a menu of options.
- Keep the brand coherent across message, visual choices, page structure, and CTA.
- Separate facts, assumptions, and aspirations.
- Make every deliverable usable without another branding session.
- Defer elaborate logos, extensive brand guidelines, multi-page sites, large content calendars, and paid acquisition until launch evidence justifies them.
- For personal-brand positioning, use `brand-positioning` when the user needs a deep positioning system, bios, proof-asset mapping, or ongoing identity refinement.
