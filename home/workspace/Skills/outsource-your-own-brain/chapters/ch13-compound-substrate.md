# Compound Knowledge — the Substrate as an Asset (Ch. 13)

**Tool vs asset:** a hammer does the same thing on day five as day one. An asset pays more for the same input over time. The substrate compounds *only* if you stop treating each AI interaction as a one-shot.

The core behavioral shift: **every project ends with 30 minutes of agent maintenance, not agent forgetting.** Save the agent config that produced the deliverable, tag the prompt-chain version, and write one line in the project AGENTS.md on what changed. That 30 minutes is the only barrier between an AI tool and an AI asset. The client pays for v4 of the manuscript; you keep v4 of the agent.

The second solopreneur (vs the one who re-pastes stale prompts and relearns her own chain): she clones v1.1, adjusts with what she's learned, runs cold in 18 minutes. New competitors can buy the same models; they cannot buy your version history.

**The 1000-day view.** The substrate runs on a ~three-year clock, not the 7-day client cycle:
- Days 0-100: first working agent + thin substrate.
- Days 100-500: payback — residue accelerates the next agent.
- Days 500-1000: compounding — the portfolio makes the marginal agent cheaper, faster, more reliable.

Anchor the substrate in files that outlive models (markdown memory, SKILL.md/AGENTS.md instructions, versioned prompts). An agent first written May 2025 survived three model swaps and now runs 4x faster with better quality — the prompts didn't get smarter; the substrate they sit on did.

**Exit-value thinking.** Pure services ≈ 1x revenue (clients + reputation walk out with you). Asset-layer businesses command 2x-5x. The substrate qualifies: versioned agents + memory tree of client preferences + brand-voice model + pricing playbook = a partial copy of your brain that a new operator can run on day one. Even if you never sell, the prep (AGENTS.md, tagged releases) is what makes sabbaticals, contractor onboarding, and stepping back possible.

**The portfolio of versioned agents** — semantically named, version-controlled, documented entries:

| Agent | v | Job | Reused since |
|---|---|---|---|
| research-agent | v2.4 | Multi-source interview prep | 11 projects |
| outline-agent | v1.8 | Outline from messy notes | 14 projects |
| voice-clone-drafter | v2.1 | Draft in client voice from sample | 6 projects |
| session-summary | v2.0 | Post-call summary + actions | 38 projects |

Each entry in Agents.md: name, current version, job, when to call, input, output. Each agent gets a SKILL.md workflow and a memory note of what recent runs learned. Treat agents like micro-SaaS: discrete job, stable interface, revved when behavior changes. Build half a dozen small ones, version quarterly, keep notes between versions — they pull ahead in 18 months not because their agents are better, but because their portfolio is.
